| 组件 | 当前版本 | 目标版本 | 说明 |
|---|---|---|---|
| Spring Boot | 2.2.6.RELEASE | 2.7.18 | 与 Dubbo 3.3 / ShardingSphere 5.5 兼容最好 |

# 1. Maven 依赖改造（root pom.xml）

## 1.1 版本属性
```xml
<java.version>11</java.version>
<dubbo.version>3.3.0</dubbo.version>
<nacos-client.version>2.5.4</nacos-client.version>
<seata.version>2.5.0</seata.version>
<sharding-sphere.version>5.5.3</sharding-sphere.version>
<mybatis-plus.version>3.5.7</mybatis-plus.version>
<mysql-connector.version>8.2.0</mysql-connector.version>
```

## 1.2 Dubbo 依赖替换
- 移除：
  - `dubbo-configcenter-nacos`
  - `dubbo-registry-nacos`
  - `dubbo-metadata-report-nacos`
  - `org.apache.dubbo:dubbo`（核心包已由 `dubbo-spring-boot-starter` 传递引入）
- 保留/升级：
  - `org.apache.dubbo:dubbo-spring-boot-starter:3.3.0`
- 新增：
  - `org.apache.dubbo:dubbo-nacos-spring-boot-starter:3.3.0`（集中管理 nacos-client 等依赖）

## 1.3 Seata 依赖替换
- `io.seata:seata-spring-boot-starter` → `org.apache.seata:seata-spring-boot-starter:2.5.0`
- 保留 ShardingSphere 的 Seata AT 集成：
  - `org.apache.shardingsphere:shardingsphere-transaction-base-seata-at:5.5.3`

## 1.4 ShardingSphere 依赖替换
- 移除：
  - `sharding-jdbc-core`
  - `sharding-jdbc-spring-boot-starter`
- 新增：
  - `org.apache.shardingsphere:shardingsphere-jdbc:5.5.3`
- `HikariCP` 改为通过官方 `spring-boot-starter-jdbc` 引入；`httpclient` 项目中未使用，已移除。
- `lombok` 等由 Spring Boot 2.7 父工程统一管理版本，无需在 root pom 中重复声明版本。

## 1.5 MySQL 驱动替换
- `mysql:mysql-connector-java:5.1.47` → `com.mysql:mysql-connector-j:8.2.0`（8.0.33 存在 CVE-2023-22102，建议升级到 ≥8.2.0）

## 1.6 传递依赖安全漏洞修复

在 root pom 的 `<properties>` 和 `<dependencyManagement>` 中覆盖 Spring Boot 2.7 默认/各 starter 传递引入的易受攻击版本：

```xml
<properties>
    <snakeyaml.version>2.2</snakeyaml.version>
    <jackson-bom.version>2.15.4</jackson-bom.version>
    <netty.version>4.1.138.Final</netty.version>
    <protobuf-java.version>3.25.5</protobuf-java.version>
    <micrometer-core.version>1.15.12</micrometer-core.version>
    <fastjson.version>2.0.52</fastjson.version>
</properties>
```

```xml
<dependencyManagement>
    <dependencies>
        <!-- Netty BOM 统一升级 Seata 传递引入的 netty-all 及各模块 -->
        <dependency>
            <groupId>io.netty</groupId>
            <artifactId>netty-bom</artifactId>
            <version>${netty.version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
        <dependency>
            <groupId>io.netty</groupId>
            <artifactId>netty-all</artifactId>
            <version>${netty.version}</version>
        </dependency>

        <!-- Dubbo 传递引入的 protobuf-java -->
        <dependency>
            <groupId>com.google.protobuf</groupId>
            <artifactId>protobuf-java</artifactId>
            <version>${protobuf-java.version}</version>
        </dependency>

        <!-- Nacos Client 传递引入的 micrometer-core -->
        <dependency>
            <groupId>io.micrometer</groupId>
            <artifactId>micrometer-core</artifactId>
            <version>${micrometer-core.version}</version>
        </dependency>

        <!-- Seata 传递引入的 fastjson（升级至 fastjson2 兼容包） -->
        <dependency>
            <groupId>com.alibaba</groupId>
            <artifactId>fastjson</artifactId>
            <version>${fastjson.version}</version>
        </dependency>
    </dependencies>
</dependencyManagement>
```

> 说明：Spring Boot 2.7.18 已停止开源维护，`spring-boot` / `spring-boot-autoconfigure` 自身的 CVE 无法通过版本覆盖修复。若需彻底消除这些核心告警，需升级到 Spring Boot 3.x（要求 JDK 17+）。

# 2. ShardingSphere 配置迁移（4.x Starter → 5.x JDBC Driver）

ShardingSphere 5.3.0+ 已移除 Spring Boot Starter，统一使用 `ShardingSphereDriver` + 独立 YAML 配置文件。

## 2.1 每个服务新增 `sharding.yaml`

以 `samples-order-service` 为例：

```yaml
dataSources:
  ds0:
    dataSourceClassName: com.zaxxer.hikari.HikariDataSource
    driverClassName: com.mysql.cj.jdbc.Driver
    jdbcUrl: jdbc:mysql://127.0.0.1:3306/ds1?useUnicode=true&characterEncoding=UTF-8&useSSL=false&serverTimezone=Asia/Shanghai
    username: root
    password: 123456

rules:
  - !SHARDING
    tables:
      t_order:
        actualDataNodes: ds0.t_order$->{0..1}
        tableStrategy:
          standard:
            shardingColumn: user_id
            shardingAlgorithmName: t_order_inline
    shardingAlgorithms:
      t_order_inline:
        type: INLINE
        props:
          algorithm-expression: t_order$->{user_id % 2}

props:
  sql-show: true

transaction:
  defaultType: BASE
  providerType: Seata
```

账户、库存服务同理，分片键分别为 `id`。

## 2.2 `application.yml` 数据源简化

```yaml
spring:
  datasource:
    driver-class-name: org.apache.shardingsphere.driver.ShardingSphereDriver
    url: jdbc:shardingsphere:classpath:sharding.yaml
```

移除原 `spring.shardingsphere.*` 整段配置。

## 2.3 `seata.conf` 更新

每个服务的 `seata.conf` 改为 ShardingSphere 5.x 所需格式：

```hocon
shardingsphere.transaction.seata.at.enable = true
shardingsphere.transaction.seata.tx.timeout = 60

client {
    application.id = order-seata-example
    transaction.service.group = order-service-seata-service-group
}
```

# 3. Dubbo 3.3 改造

## 3.1 注解清理
- `samples-storage-service/src/main/java/.../dubbo/StorageDubboServiceImpl.java`
  - 删除未使用的 `org.apache.dubbo.config.annotation.Service` 导入
- `samples-order-service/src/main/java/.../service/TOrderServiceImpl.java`
  - 将 `@Reference` 替换为 `@DubboReference`

## 3.2 服务实现类注解（可保留，但建议简化）
当前：
```java
@DubboService(version = "1.0.0", protocol = "${dubbo.protocol.id}",
              application = "${dubbo.application.id}", registry = "${dubbo.registry.id}", timeout = 30000)
```
建议改为：
```java
@DubboService(version = "1.0.0", timeout = 30000)
```

## 3.3 `application.yml` Dubbo 配置简化

以 `samples-order-service` 为例：

```yaml
dubbo:
  application:
    name: dubbo-order-example
    qosEnable: false
  protocol:
    name: dubbo
    port: 20880
  registry:
    address: nacos://127.0.0.1:8848?namespace=40508bb4-179e-4c98-a2f1-c2c031c20b3c
  consumer:
    check: false
    retries: 0
```

- 移除 `dubbo.application.id`（Dubbo 3 优先使用 name）
- 移除 `dubbo.registry.id`
- 移除 `dubbo.config-center` 和 `dubbo.metadata-report`（`dubbo-nacos-spring-boot-starter` 会统一管理；如需要可在 `dubbo.metadata-report.address` 单独配置）

## 3.4 启动类
- 保留 `@EnableDubbo(scanBasePackages = "...")`
- `BusinessExampleApplication` 中移除 `SpringBootConfiguration.class` 的 exclude（ShardingSphere 5 已无该 Spring Boot 自动配置类）

# 4. Seata 2.5 改造

## 4.1 Java 代码
- 包名：`io.seata.*` → `org.apache.seata.*`
  - `io.seata.core.context.RootContext` → `org.apache.seata.core.context.RootContext`
  - `io.seata.spring.annotation.GlobalTransactional` → `org.apache.seata.spring.annotation.GlobalTransactional`
- 涉及文件：
  - `samples-business-service/.../BusinessServiceImpl.java`
  - `samples-account-service/.../dubbo/AccountDubboServiceImpl.java`
  - `samples-order-service/.../dubbo/OrderDubboServiceImpl.java`
  - `samples-order-service/.../service/TOrderServiceImpl.java`
  - `samples-storage-service/.../dubbo/StorageDubboServiceImpl.java`

## 4.2 `application.yml` Seata 配置更新

以 `samples-order-service` 为例：

```yaml
seata:
  enabled: true
  application-id: order-seata-example
  tx-service-group: order-service-seata-service-group
  service:
    vgroup-mapping:
      order-service-seata-service-group: default
  registry:
    type: nacos
    nacos:
      application: seata-server
      server-addr: localhost:8848
      namespace: 40508bb4-179e-4c98-a2f1-c2c031c20b3c
      group: SEATA_GROUP
      cluster: default
  config:
    type: nacos
    nacos:
      server-addr: localhost:8848
      namespace: 40508bb4-179e-4c98-a2f1-c2c031c20b3c
      group: SEATA_GROUP
  enable-auto-data-source-proxy: false
```

- `enable-auto-data-source-proxy` 必须改为 `false`（ShardingSphere 5 自己管理 Seata AT 连接）
- `tx-service-group` 与 `service.vgroup-mapping` 必须配套

- 按 Seata 2.5 官方 `server/db/mysql.sql` 初始化 Seata Server 的 `global_table`、`branch_table`、`lock_table`

# 5. Nacos 2.5.4 改造

## 5.1 依赖
- 通过 `dubbo-nacos-spring-boot-starter` 引入 Nacos Client；版本由 root pom 的 `<dependencyManagement>` 锁定为 `2.5.4`，不再直接声明 `nacos-client` 依赖。
- 子模块对 `samples-common-service` 的依赖版本由 root pom 的 `<dependencyManagement>` 统一声明，子 pom 中不再写版本。

## 5.2 端口与协议
- Nacos 2.x 默认同时监听 8848（HTTP）和 9848（gRPC）
- 配置中仍写 `localhost:8848`，但需确保 9848 端口可达

## 5.3 Dubbo / Seata 的 Nacos 配置
- Dubbo 注册中心：`dubbo.registry.address=nacos://127.0.0.1:8848?namespace=...`
- Seata 注册/配置中心：见 4.2 节

# 7. Spring Boot 2.7 升级影响

## 7.1 配置文件加载
- Spring Boot 2.7 仍支持 `spring.factories`，但建议迁移到 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`
- 本项目不做自定义 starter，通常无需改动

## 7.2 建议同步升级
- MyBatis-Plus 3.3.1 → 3.5.7
- Lombok 1.18.12 → 1.18.30（可选）
- HikariCP 3.3.1 可保留，也可升级到 4.x/5.x

## 7.3 `spring.datasource` 与 ShardingSphereDriver
- 由于使用 `ShardingSphereDriver`，Spring Boot 的 `DataSourceAutoConfiguration` 会自动创建 HikariCP DataSource，无需再 exclude `DataSourceAutoConfiguration`（业务服务 `business-service` 没有数据库，仍可 exclude）

# 10. 风险与回滚

| 风险点 | 说明 |
|---|---|
| ShardingSphere 5 配置格式大变 | 所有 `spring.shardingsphere.*` 都要迁到 `sharding.yaml` |
| Seata 2.x + ShardingSphere 5 的依赖冲突 | 需排除 `org.antlr:antlr4-runtime` 等冲突包 |
| Nacos 2.x gRPC 端口 | 必须开放 9848，否则服务无法注册/发现 |
| Dubbo 3.3 默认 hessian2 | 与 Dubbo 2.7 互通可能有问题；本项目全部升级，无需考虑 |
| MySQL 8.0 认证插件 | 老用户可能是 `mysql_native_password`，需按实际情况调整 |

建议：在版本控制中创建独立分支；每完成一个组件升级即提交一次，方便分阶段回滚。
