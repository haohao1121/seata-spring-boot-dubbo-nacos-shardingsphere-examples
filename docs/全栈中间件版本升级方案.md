> 说明：本方案描述的升级工作已在当前代码库中完成。下文中的版本、依赖、配置均为项目当前实际使用的最终状态，可直接作为环境搭建与问题排查的参考。

## 1.6 传递依赖安全漏洞修复

在 root pom 的 `<dependencyManagement>` 中覆盖 Spring Boot 2.7 默认 / 各 starter 传递引入的易受攻击版本：

```xml
<dependencyManagement>
    <dependencies>
        <!-- ShardingSphere 5.5.3 需要 commons-lang3 >= 3.13，覆盖其传递的 3.12.0 -->
        <dependency>
            <groupId>org.apache.commons</groupId>
            <artifactId>commons-lang3</artifactId>
            <version>${commons-lang3.version}</version>
        </dependency>

        <!-- Netty BOM：统一升级 Seata 传递引入的 netty-all 及各模块 -->
        <dependency>
            <groupId>io.netty</groupId>
            <artifactId>netty-bom</artifactId>
            <version>${netty.version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
        <dependency>
            <groupId>io.netty</groupId>
            <artifactId>netty-all</artifactId>
            <version>${netty.version}</version>
        </dependency>

        <!-- 修复 Dubbo 传递引入的 protobuf-java 漏洞 -->
        <dependency>
            <groupId>com.google.protobuf</groupId>
            <artifactId>protobuf-java</artifactId>
            <version>${protobuf-java.version}</version>
        </dependency>

        <!-- 修复 Nacos Client 传递引入的 micrometer-core 漏洞 -->
        <dependency>
            <groupId>io.micrometer</groupId>
            <artifactId>micrometer-core</artifactId>
            <version>${micrometer-core.version}</version>
        </dependency>

        <!-- 修复 Seata 传递引入的 fastjson 漏洞 -->
        <dependency>
            <groupId>com.alibaba</groupId>
            <artifactId>fastjson</artifactId>
            <version>${fastjson.version}</version>
        </dependency>
    </dependencies>
</dependencyManagement>
```

> 说明：Spring Boot 2.7.18 已停止开源维护，`spring-boot` / `spring-boot-autoconfigure` 自身的 CVE 无法通过版本覆盖修复。若需彻底消除这些核心告警，需升级到 Spring Boot 3.x（要求 JDK 17+）。

# 2. ShardingSphere 配置（5.x JDBC Driver 模式）

ShardingSphere 5.3.0+ 已移除 Spring Boot Starter，统一使用 `ShardingSphereDriver` + 独立 YAML 配置文件。

## 2.1 每个服务新增 `sharding.yaml`

以 `samples-order-service` 为例（`ds1` 库，`user_id` 为分片键）：

```yaml
dataSources:
  ds0:
    dataSourceClassName: com.zaxxer.hikari.HikariDataSource
    driverClassName: com.mysql.cj.jdbc.Driver
    jdbcUrl: jdbc:mysql://127.0.0.1:3306/ds1?useUnicode=true&characterEncoding=UTF-8&useSSL=false&serverTimezone=Asia/Shanghai
    username: root
    password: 123456

rules:
  - !SHARDING
    tables:
      t_order:
        actualDataNodes: ds0.t_order$->{0..1}
        tableStrategy:
          standard:
            shardingColumn: user_id
            shardingAlgorithmName: t_order_inline
    shardingAlgorithms:
      t_order_inline:
        type: INLINE
        props:
          algorithm-expression: t_order$->{user_id % 2}

props:
  sql-show: true

transaction:
  defaultType: BASE
  providerType: Seata
```

- `samples-account-service`：`ds0` 库，`t_account` 按 `id` 取模分片。
- `samples-storage-service`：`ds2` 库，`t_storage` 按 `id` 取模分片，并配置了 SNOWFLAKE 主键生成器。

## 2.2 `application.yml` 数据源简化

```yaml
spring:
  datasource:
    driver-class-name: org.apache.shardingsphere.driver.ShardingSphereDriver
    url: jdbc:shardingsphere:classpath:sharding.yaml
```

原 `spring.shardingsphere.*` 配置已整体移除。

## 2.3 `seata.conf` 更新

每个服务的 `seata.conf` 改为 ShardingSphere 5.x 所需格式：

```hocon
shardingsphere.transaction.seata.at.enable = true
shardingsphere.transaction.seata.tx.timeout = 60

client {
    application.id = order-seata-example
    transaction.service.group = default_tx_group
}
```

> 当前所有服务统一使用事务分组 `default_tx_group`，与 Nacos 中 `seataServer.properties` 的 `service.vgroupMapping.default_tx_group=default` 保持一致。

# 4. Seata 2.5 配置

## 4.1 Java 代码

包名迁移：`io.seata.*` → `org.apache.seata.*`

- `io.seata.core.context.RootContext` → `org.apache.seata.core.context.RootContext`
- `io.seata.spring.annotation.GlobalTransactional` → `org.apache.seata.spring.annotation.GlobalTransactional`

涉及文件已在第 3.1 节列出。

## 4.2 `application.yml` Seata 配置

以 `samples-order-service` 为例：

```yaml
seata:
  enabled: true
  application-id: order-seata-example
  tx-service-group: default_tx_group
  service:
    vgroup-mapping:
      default_tx_group: default
  registry:
    type: nacos
    nacos:
      application: seata-server
      server-addr: localhost:8848
      namespace: lli-dubbo-seata-nacos-mysql
      group: SEATA_GROUP
      cluster: default
      username: nacos
      password: nacos
  config:
    type: nacos
    nacos:
      server-addr: localhost:8848
      namespace: lli-dubbo-seata-nacos-mysql
      group: SEATA_GROUP
      dataId: seataServer.properties
      username: nacos
      password: nacos
  enable-auto-data-source-proxy: false
```

关键点：
- `enable-auto-data-source-proxy` 必须设为 `false`（ShardingSphere 5 自己管理 Seata AT 连接）。
- `tx-service-group` 与 `service.vgroup-mapping` 必须配套。
- Nacos 命名空间使用当前项目的命名空间 `lli-dubbo-seata-nacos-mysql`。

## 4.3 Seata Server 配置（`docs/seata-server.properties`）

当前配置示例：

```properties
store.mode=db
store.lock.mode=db
store.session.mode=db
store.db.dbType=mysql
store.db.datasource=druid
store.db.driverClassName=com.mysql.cj.jdbc.Driver
store.db.url=jdbc:mysql://mysql:3306/seata?useUnicode=true&characterEncoding=utf-8&useSSL=false&serverTimezone=Asia/Shanghai&zeroDateTimeBehavior=convertToNull
store.db.user=root
store.db.password=123456
store.db.minConn=5
store.db.maxConn=30
store.db.queryLimit=100
store.db.maxWait=5000
store.db.globalTable=global_table
store.db.branchTable=branch_table
store.db.lockTable=lock_table
store.db.distributedLockTable=distributed_lock
service.vgroupMapping.default_tx_group=default
```

## 4.4 SQL 脚本

- 业务库（`ds0`、`ds1`、`ds2`）需按 Seata 2.5 官方 `client/at/db/mysql.sql` 创建 `undo_log` 表。
- Seata Server 库（`seata`）需按 Seata 2.5 官方 `server/db/mysql.sql` 初始化 `global_table`、`branch_table`、`lock_table`、`distributed_lock`、`vgroup_table`。
- 项目已将这些脚本聚合到 `sql/init.sql` 中，可直接执行。

# 5. Nacos 2.5.4 配置

## 5.1 依赖

- 通过 `dubbo-nacos-spring-boot-starter` 引入 Nacos Client。
- 版本由 root pom 的 `<dependencyManagement>` 锁定为 `2.5.4`，不再直接声明 `nacos-client` 依赖。
- 子模块对 `samples-common-service` 的依赖版本由 root pom 的 `<dependencyManagement>` 统一声明，子 pom 中不再写版本。

## 5.2 端口与协议

- Nacos 2.x 默认同时监听 8848（HTTP）和 9848（gRPC）。
- 配置中仍写 `localhost:8848`，但需确保 9848 端口可达。

## 5.3 Dubbo / Seata 的 Nacos 配置

- Dubbo 注册中心：`nacos://127.0.0.1:8848?namespace=lli-dubbo-seata-nacos-mysql&username=nacos&password=nacos`
- Seata 注册/配置中心：见 4.2 节。

> 注意：Nacos 2.x 中 namespace 的**显示名称**与**ID** 不能混用。客户端配置中的 `namespace` 必须填写 namespace 的 ID（或自定义 ID，如本项目的 `lli-dubbo-seata-nacos-mysql`），填写显示名称会导致客户端静默失败。

# 9. 验证计划

1. 执行 `sql/init.sql` 初始化 MySQL 数据库。
2. 启动 Nacos 2.5.4 standalone 模式（确保 8848/9848 端口开放）。
3. 在 Nacos 中上传 `docs/seata-server.properties`（Group：`SEATA_GROUP`，DataId：`seataServer.properties`）。
4. 启动 Seata Server 2.5.0，确认注册到 Nacos。
5. 执行 `mvn clean compile -DskipTests` 全工程编译通过。
6. 依次启动 `samples-account-service`、`samples-order-service`、`samples-storage-service`、`samples-business-service`：
   - 检查 ShardingSphereDriver 成功加载 `sharding.yaml`。

   - 正常下单：`POST http://localhost:8104/business/dubbo/buy`

8. 验证正常下单成功、异常时全局回滚成功。
9. 检查各业务库 `undo_log` 是否有正常写入/清理。

# 10. 风险与回滚

| 风险点 | 说明 |
|---|---|
| ShardingSphere 5 配置格式大变 | 所有 `spring.shardingsphere.*` 都要迁到 `sharding.yaml` |
| ShardingSphere 5.5.3 SPI 模块缺失 | 必须显式引入 `shardingsphere-sharding-core`、`shardingsphere-infra-url-classpath`、`shardingsphere-infra-data-source-pool-hikari`、`shardingsphere-standalone-mode-repository-memory`、`shardingsphere-authority-simple`、`shardingsphere-parser-sql-engine-mysql` 等模块 |
| Seata 2.x + ShardingSphere 5 的依赖冲突 | 需通过 `dependencyManagement` 锁定 Netty、protobuf-java、micrometer-core、fastjson、commons-lang3 等版本 |
| Nacos 2.x gRPC 端口 | 必须开放 9848，否则服务无法注册/发现 |
| Nacos namespace 显示名称问题 | 填写显示名称而非 ID 会导致客户端静默失败 |
| Dubbo 3.3 默认 hessian2 | 与 Dubbo 2.7 互通可能有问题；本项目全部升级，无需考虑 |
| MySQL 8.0 认证插件 | 老用户可能是 `mysql_native_password`，需按实际情况调整 |
| Maven 构建告警 | Seata 2.5.0 传递依赖 Druid 会拉入大量 `provided` 范围的 Hadoop/Hive/HSF 相关 artifact，产生 POM missing / effective model 告警；这些依赖不影响运行，可通过排除 `edas-sdk` 等方式进一步清理 |

建议：在版本控制中创建独立分支；每完成一个组件升级即提交一次，方便分阶段回滚。
